규칙팀원마다 다른 AI 도구(Claude Code, GitHub Copilot, Cursor, OpenAI Codex, Gemini)를 씁니다. 규칙은 AGENTS.md 하나(약 60줄)에 두고, 도구별 파일(CLAUDE.md, copilot-instructions.md, .cursor/rules/, GEMINI.md)은 이 파일을 먼저 읽게 합니다.

흐름이슈 하나가 머지되기까지 7단계입니다. 이슈 등록 → AI 분류(라벨 부여) → 사람이 ai:ready 부여 → AI 구현(테스트 먼저, 별도 worktree) → 초안 PR · CI · AI 리뷰(참고용) → 사람 CODEOWNER 승인 → squash 머지 · ai:done · 릴리스 PR. 초안 PR을 ready로 바꾸고 머지하는 것도 리뷰어가 합니다. AI 작업은 각자 자리에서 본인의 claude 로그인으로, API 키 없이 실행합니다(make ai-triage / ai-review / ai-implement / ai-queue).

내 PC내 PC에서 먼저 막습니다. Claude Code 플러그인 team-ai-workflow의 훅이 보호 경로(비밀 파일, 락파일, CODEOWNERS, 룰셋, .claude/settings.json) 수정과 main 커밋, 공유 브랜치 강제 푸시를 차단하고, 수정 직후 포맷합니다. 훅은 Claude Code에서만 동작하므로 다른 도구의 변경은 pre-commit(비밀·형식 검사)과 CI와 같은 명령인 make check로 확인합니다. 사람의 커밋에도 같이 적용됩니다.

GitHubGitHub 쪽에서 같은 규칙으로 한 번 더 검사합니다. 룰셋이 PR, 사람 승인, ci-ok, squash 머지만 허용하고, CODEOWNERS, CodeQL(기본은 워크플로 파일), 비밀 스캔, Dependabot이 함께 동작합니다. 룰셋과 비밀 스캔은 관리자가 make github-setup으로 한 번 적용합니다. AI 리뷰는 참고용이라 승인으로 세지 않고, agent-approval-check가 Claude·Copilot 커밋이 든 PR의 사람 승인을 한 번 더 확인합니다.
